Summary:
This is a follow up on defect/enhancment request CSCvq91933. 

In NX-OS Version 10.1(1) and presumably all others, the TACACS+ "single-connect" flag is not set, even with "single-connection" CLI enabled.

If NX-OS will not set the single-connection flag in TACACS header, the CLI should not be available in code. 

Here is the draft and RFC which we are not compliant with: https://tools.ietf.org/id/draft-ietf-opsawg-tacacs-08.html
RFC: https://datatracker.ietf.org/doc/html/rfc8907#section-4.3

The implementation is not as simple as it looks at the outset.. not just matter of setting a flag in outgoing TACACS packets. Apart from other things, the highlighted
 part below from the RFC makes the implementation a bit complex. TACACS client (on switch) would be needing to do a handshake with the server each time a single-connect based connection is established. In turn, TACACS client (on switch) would require to enqueue
 incoming requests until the single-connect handshake with the server is through. Use cases around wear-and-tear of an existing single-connect connection and the re-establishment of such connection would only add fuel to the fire. Need proper UT cycles as well
 to avoid any regressions to the existing functionality.
