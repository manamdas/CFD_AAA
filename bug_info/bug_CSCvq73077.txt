Summary:
If using TACACS+ or RADIUS authorization and passing multiple roles in the "shell:roles" AV pair, the Linux group membership of the newly created user depends only on the first role in the AV pair. The rest of the roles are disregarded as far as the Linux group membership of the user is concerned. In other words, the newly created user will be placed only into Linux groups based on the first role from the "shell:roles" AV pair; other roles will be ignored.

As an example:

With "shell:roles = network-admin vdc-admin":

switch# sh user-account
user:test1
        roles:network-admin vdc-admin
^^^ Both roles are recognized here

switch# run bash
bash-4.3$ id
uid=2004(test1) gid=503(network-admin) groups=503(network-admin),504(network-operator)
^^^ User placed only into network-admin and network-operator groups, not vdc-admin

With "shell:roles = vdc-admin network-admin":

switch# sh user-account
user:test1
        roles:vdc-admin network-admin
^^^ Both roles are recognized here

switch# run bash
bash-4.3$ id
uid=2004(test1) gid=504(network-operator) groups=504(network-operator),528(vdc-admin)
^^^ User placed only into network-operator and vdc-admin groups, not network-admin

---Start of Note Titled:  Release-note (Created 07/31/2019 00:38:14 Modified 08/06/2019 02:16:57 by vasagraw)---
<B>Symptom:</B>
If using TACACS+ or RADIUS authorization and passing multiple roles in the "shell:roles" AV pair, the Linux group membership of the newly created user depends only on the first role in the AV pair. The rest of the roles are disregarded as far as the Linux group membership of the user is concerned. In other words, the newly created user will be placed only into Linux groups based on the first role from the "shell:roles" AV pair; other roles will be ignored.

As an example:

With "shell:roles = network-admin vdc-admin":

switch# sh user-account
user:test1
        roles:network-admin vdc-admin
^^^ Both roles are recognized here

switch# run bash
bash-4.3$ id
uid=2004(test1) gid=503(network-admin) groups=503(network-admin),504(network-operator)
^^^ User placed only into network-admin and network-operator groups, not vdc-admin

With "shell:roles = vdc-admin network-admin":

switch# sh user-account
user:test1
        roles:vdc-admin network-admin
^^^ Both roles are recognized here

switch# run bash
bash-4.3$ id
uid=2004(test1) gid=504(network-operator) groups=504(network-operator),528(vdc-admin)
^^^ User placed only into network-operator and vdc-admin groups, not network-admin

<B>Conditions:</B>
Using RADIUS or TACACS+ authentication with multiple roles in shell:roles AV pair.

<B>Workaround:</B>
admin can create the missing roles manually for the impacted user
