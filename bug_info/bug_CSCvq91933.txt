Summary:
Nexus 9K does not support TACACS+ IETF draft compliant single-connect.


We are not compliant with the original TACACS+ Draft from 1998. It is a Cisco IETF draft: https://tools.ietf.org/html/draft-grant-tacacs-02
We are not compliant with current TACACS+ Protocol IETF draft: https://tools.ietf.org/html/draft-ietf-opsawg-tacacs-13

Legacy mode is a buggy behavior and it needs to be fixed.

"The legacy mode comes from ACS 4.x will implements single-connect more optimistically to work around some buggy (Cisco) devices. Basically, some Cisco devices did not set the single-connect flag in the header, despite configuring single-connect on the device. Consequently, the T+ server would disconnect the TCP connection after the first response and the device could not do single-connect. Really, it was a bug in the device but its always a bigger issue asking customers to upgrade device firmware than do a workaround in the T+ server. So ACS 4 (and now 5) have this legacy mode which basically ignores the single-connect flag but instead leaves the TCP connection open until it sees the device explicitly close its end. This has the advantage of working in single-connect mode or not automatically, irrespective of the single-connect flag in the header."
Link whole discussion: https://search-prd.cisco.com/topic/news/cisco/eng/cse-dev-acs5/dsc08610.html

<B>Symptom:</B>
With current legacy Cisco TACACS+ client implementation Nexus do not set the single-connect flag in the header, despite configuring single-connect mode on the device. TACACS+ Protocol IETF draft  compliant server disconnects the TCP connection after the first response and the device could not do single-connect.

<B>Conditions:</B>
This issue happens only for 3rd party TACACS+ servers. Cisco ISE and ACS has an option to disable the header verification by choosing the Legacy Cisco Device option. This legacy mode basically ignores the single-connect flag, but instead leaves the TCP connection open until it sees the device explicitly close its end.

<B>Workaround:</B>
Disable single-connect mode, or use Cisco TACACS+ servers.
