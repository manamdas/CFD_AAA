---Start of Note Titled:  Eng-Notes (Created 04/15/2020 09:02:37 Modified 04/18/2020 07:46:50 by sukumars)---
'enable secret' is not supported (yes yes, we get it, then why you have the command  still)  in NxOS, as RBACL
supports superior user access control based on privilege levels, and in addition passwords on RBACL (username x password y ) 
uses more secure SHA256 encryption, while 'enable secret..' uses Md5 weak  encryption.

Long story,  'enable secret' was added in NxOS to support IOS to  NxOS config migration as a transition feature. It should have been long removed (get get, we should have removed).

Pls advise your customers not use 'enable secret' and instead use 'RBACL' in NxOS, until we deprecate 'enable secret' after reviewing any upgrade/existing customer usage implications.

We have updated  documentation for Command reference and Config guide for ?enable secret? usage and deprecation:
 
https://www.cisco.com/c/en/us/td/docs/switches/datacenter/nexus9000/sw/9-x/command_references/921/config/b_N9K_Config_Commands_921/b_N9K_Config_Commands_921_chapter_0101.html#wp1160990493
 
Warning
Do not use this command. This command is deprecated, is not supported, and will not be available in future releases. As an alternative, use RBAC rules, which provide more granular security control. For more information on RBAC refer to "Configuring User Accounts and RBAC" in the Cisco Nexus 9000 Series NX-OS Security Configuration Guide.
 
and Config Guide also where it appears:
 
https://www.cisco.com/c/en/us/td/docs/switches/datacenter/nexus9000/sw/93x/security/configuration/guide/b-cisco-nexus-9000-nx-os-security-configuration-guide-93x.pdf
 
Warning: Do not use the enable secret command. This command is not supported and is being deprecated. It will not
be available in future releases. As an alternative, use RBAC rules, which provide more granular security
control. For more information on RBAC, see "Configuring User Accounts and RBAC" in the Cisco Nexus
9000 Series NX-OS Security Configuration Guide.

In addition for years,  NxOS  Hardening guide public documentation documents to *not* use enable secret.

https://tools.cisco.com/security/center/resources/securing_nx_os.html

"The enable secret command is used in Cisco IOS Software to set a password that grants privileged administrative access to a Cisco IOS Software system. In Cisco NX-OS, there is no concept of an enable-secret or enable-password setting. Privileges are managed using role-based access control (RBAC). The functional equivalent to enabling mode access on a Cisco IOS Software device is assignment of an account to the network-admin (global privileged access) or vdc-admin (virtual device context [VDC]-specific privileged access) role in Cisco NX-OS."

<B>Symptom:</B>
A vulnerability in the Enable Secret feature of Cisco Nexus 3000 Series Switches and Cisco Nexus 9000 Series Switches in standalone NX-OS mode could allow an authenticated, local attacker to issue the enable command and get full administrative privileges. To exploit this vulnerability, the attacker would need to have valid credentials for the affected device.

The vulnerability is due to a logic error in the implementation of the enable command. An attacker could exploit this vulnerability by logging in to the device and issuing the enable command. A successful exploit could allow the attacker to gain full administrative privileges without using the enable password.

Note: The Enable Secret feature is disabled by default.

Cisco has released software updates that address this vulnerability. There are workarounds that address this vulnerability.

This advisory is available at the following link:
https://tools.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-n3n9k-priv-escal-3QhXJBC
