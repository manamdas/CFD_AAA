Summary:
In earlier release of NX switches, when we send multiple VSA from the radius server, and one of the attributes is invalid, the NX will skip this attributes and check the next one inline so the role will be assigned correctly. In release 10.2.5, the behavior changed, after checking the invalid VSA, it will not move to the next VSA and assign an incorrect role to the user.

---Start of Note Titled:  Release-note (Created 09/25/2023 23:57:52 Modified 01/11/2024 20:26:40 by palshanm)---
<B>Symptom:</B>
After the upgrade to release 10.2.5, the role assigned to the user is incorrect ( will be assigned as network operator instead of network admin) however, attributes shared by the Radius server contains admin role VSA.

<B>Conditions:</B>
upgrade to 10.2.5

The below attributes were sent from the Radius server, since the first attribute is not valid one[role] not system/custom attribute, the new code of NX (10.2(5)) will not proceed with checking the next attributes and assign a network operator role to the admin user.

Cisco-av-pair=shell:role=SUPER-ADMIN-ROLE
Cisco-av-pair= shell:priv-lvl=15                                                                   
Cisco-av-pair=NCS:virtual-domain0=ROOT-DOMAIN
Cisco-av-pair=shell:domain=all/admin/read-all
Cisco-av-pair=NCS:role0=Super Users
Cisco-av-pair=shell:roles="admin,aaa,network-admin,vdc-admin"

<B>Workaround:</B>
use correct VSA syntax to be sent.

<B>Further Problem Description:</B>
The issue will be fixed on the coming releases
