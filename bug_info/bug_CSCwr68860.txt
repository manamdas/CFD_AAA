1. RCA: Root cause of the problem. 
During an unsupported downgrade, TAM flag-file: /mnt/pss/tam-issu-configs survived post-reload-operations though it should have been deleted once its purpose is accomplished post-reload.. 
As a POC, I deleted this file on DUT and issue disappeared as expected. Due to this file being there, simple crs+reload was able to repro the issue.

Though even with this file being present, if TAM is not enabled, it will have no impact. but if TAM is already enabled or if enabled later at any point of time, any reload would cause to fall into this issue.

If this file survived from some previous ISSU, and if TAM is not enabled currently, it just stays there.
Its presence takes effect when TAM is enabled eventually, so post-reload, delete current KeyStore (i.e. KS) (rename it as key_store_1_old_enc), replace it with decrypted-KS.bkp (but during normal reloads we dont have any decrypted KS as it is created only in case of ISSU),. Since there is no KS, and this issue is seen.

<B>Symptom:</B>
Since master key is missing, any radius/tacacs AAA using type-6 encryption will fail
Radius/Tacacs also support type-7 encryption, which is not affected by this defect

<B>Conditions:</B>
- Unsupported downgrade was previously done which left an internal file for master key behind
- Later, enable TAM feature
- Lastly, perform upgrade or reload to reinitialize checking this file, leading to failure

<B>Workaround:</B>
Unconfigure and configure master key will resolve the issue until we reboot or upgrade to fixed version

<B>Further Problem Description:</B>
Since master key is missing, any radius/tacacs AAA using type-6 encryption will fail
Radius/Tacacs also support type-7 encryption, which is not affected by this defect

There are tam version difference between releases. When we upgrade from one tam version to another tam version, we will be handling taking up backup of master key internally and program it once DUT comes online with new tam version
