---Start of Note Titled:  Release-note (Created 07/19/2026 18:19:22 Modified 08/05/2026 03:05:02 by vasagraw)---
<B>Symptom:</B>
An unwarranted {"no username <>" + "username <>"} diff might be generated in Configure-Replace patch for a <username> CLI. If any active session is present for that user, "no username <>" from CR-patch would not get through. This will result into failure of the overall Configure-Replace operation.

<B>Conditions:</B>
The <username> CLI is functionally the same in both running-config and the CR-file. However, the two may be different syntax-wise.

EXAMPLE: On execution, the CR-FILE config would turn into the currently present RUNNING-CONFIG config. Since they both are same, no diff should be generated against this config in the CR-patch. 
RUNNING-CONFIG: username user9 password 5 ! expire 2027-01-07 role priv-2
CR-FILE: username user9 role priv-2 expire 2027-01-07

<B>Workaround:</B>
If we do not intend to change a "username <>" configuration as part of CR-operation, the CR-file should have the same configuration as is present in running-config. The two functionally same "username <>"entries should be same syntactically as well. 

<B>Further Problem Description:</B>
The issue is not easily reproducible. It was observed sporadically.
