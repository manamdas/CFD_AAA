---Start of Note Titled:  Release-note (Created 04/24/2025 01:47:55 Modified 11/23/2025 21:34:49 by palshanm)---
When the aaa group1 cannot access the TACACS Server but the source-interface remains up, the permissions obtained by the role are abnormal

<B>Symptom:</B>
When the aaa group1 cannot access the tacacs server and maintain the source-interface up, (the group2 is normal), there will be problems with the permissions obtained by the user.

The role permissions obtained through TACACS are always "network-operator" and cannot be obtained as "network-admin"

Example:
The "test" account, which should have obtained network-admin permissions, has abnormal permissions. This will make it impossible to configure the switch:

N9k# show user-account 
user:test
        roles:network-operator                                <<<<<<<<<<<<<<<<<
account created through REMOTE authentication
Credentials such as ssh server key will be cached temporarily only for this user account
Local login not possible

<B>Conditions:</B>
The aaa group1 cannot access the Tacacs server, but the group source-interface is kept up.

<B>Workaround:</B>
Remove the source-interface configuration or shut down the source-interface interface:

N9k(config)# aaa group server tacacs+ bytedance
N9k(config-tacacs+)# no source-interface loopback0

Or

N9k(config)# int loopback 0
N9k(config-if)# shutdown

<B>Further Problem Description:</B>
All accounts get abnormal roles
