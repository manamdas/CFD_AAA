Summary:
After upgrade to 9.3.5 from 7.0(3)I4(8), LDAP search-filter config got changed.

Before upgrade  :
	userprofile attribute-name "xxxx" search-filter "110charactersString" base-DN "xxxx"

After upgrade :
	userprofile attribute-name "xxxx" search-filter "63charactersString" base-DN "xxxx"


* Problem is : Not able to use all 128 characters in search filter.

N9k(config)#ldap search-map 
N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter "110charactersString" base-DN "xxxx"
ERROR: value of property searchFilter is out of range:

N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter ?
  WORD  Search Map search-filter  (Max Size 128)

* This search-filter only have 110 characters, still not accepted, where as we have limit of 128.
* Same behavior re-producible in LAB.
* Issue is not seen with 9.2.x (hamilton) only seen in Irvine (9.3.x)
* I have tested with 9.2.4 (hamilton) and 9.3.2 (Irvine)

* Tested in Lab can use only 63 character in search filter :
N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter "63charactersString" base-DN "xxxx"
N9k(config-ldap-search-map)#

---Start of Note Titled:  Release-note (Created 09/11/2020 04:02:58 Modified 10/06/2020 16:40:35 by mhadpe)---
<B>Symptom:</B>
After upgrading to Cisco NX-OS 9.3(5) from 7.0(3)I4(8), LDAP search-filter config got changed.

Before upgrade  :
	userprofile attribute-name "xxxx" search-filter "110charactersString" base-DN "xxxx"

After upgrade :
	userprofile attribute-name "xxxx" search-filter "63charactersString" base-DN "xxxx"


* Problem is : Not able to use all 128 characters in search filter.

N9k(config)#ldap search-map <searchMapName>
N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter "110charactersString" base-DN "xxxx"
ERROR: value of property searchFilter is out of range:

N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter ?
  WORD  Search Map search-filter  (Max Size 128)

* This search-filter only has 110 characters and it still not accepted. Whereas we have a limit of 128.


Update:
=====

Duplicate Bug CSCvv90135 Corrupted LDAP configuration string on 9.3(5) release

Symptom 2: LDAP config Missing post upgrade to 9.3(5) from 9.3(4)


It seems that during the upgrade - the portion of the configuration "dc=com" in the ldap-server host configuration gets changed which breaks the LDAP configuration. 

Before:

ldap-server host 10.1.85.101 rootDN "cn=svcnwldap,ou=UT Service Accounts,dc=americas,dc=unither,dc=com"  password 7 Sh3@k3Bt2QG20190717$ timeout 30
ldap search-map unithersm1
  userprofile attribute-name "extensionAttribute15" search-filter "cn=$userid" base-DN "DC=americas,DC=unither,DC=com"
aaa group server ldap ut-ldap-servers
  server 10.1.85.101
  ldap-search-map unithersm1




After:
ldap-server host 10.1.85.101 rootDN "cn=svcnwldap,ou=UT Service Accounts,dc=americas,dc=unither,dc=coSh3@k3Bt2QG20190717$"  password 7 Sh3@k3Bt2QG20190717$ timeout 30 
ldap search-map unithersm1
userprofile attribute-name "extensionAttribute15" search-filter "cn=$userid" base-DN "DC=americas,DC=unither,DC=com"
aaa group server ldap ut-ldap-servers
  server 10.1.85.101
  ldap-search-map unithersm1

<B>Conditions:</B>
*  Tested in LAB : only seen in 9.3.x release
*  Issue is not with 9.2.x

<B>Workaround:</B>
* Tested in lab. Could use only 63 character in search filter :
N9k(config-ldap-search-map)# userprofile attribute-name "xxxx" search-filter "63charactersString" base-DN "xxxx"
N9k(config-ldap-search-map)#
