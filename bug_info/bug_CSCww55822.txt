Summary:
When TACACS+ is configured on a Nexus 9000 with a source-interface other than mgmt0 (for example, a loopback or SVI) in a non-management VRF, and the TACACS+ server IP is reachable through a VXLAN-learned route, the switch does not use the configured source-interface. Instead, it sources the TACACS+ packets from the lowest IP address available in that VRF, causing authentication failures when the AAA server only accepts requests from the configured source IP.

---Start of Note Titled:  Release-note (Created 09/10/2026 12:47:03 Modified 10/14/2026 21:26:37 by vasagraw)---
<B>Symptom:</B>
TACACS+ authentication and authorization fail on a Nexus 9000. Packets sent to the TACACS+/ISE server carry an unexpected source IP instead of the IP of the configured source-interface. Because the AAA server only accepts requests from the expected source IP, the TCP session to port 49 never completes ? SYNs are retransmitted and no SYN,ACK is received. User logins fall back to local authentication or time out.

<B>Conditions:</B>
Platform: Cisco Nexus 9000 Series switch
Affected releases: Seen on NX-OS 10.5(5) and 10.6(4)
Not reproducible on: NX-OS 10.3(3x)

feature tacacs+ enabled, with a source-interface other than mgmt0 configured 
TACACS+ server reachable through a non-management VRF 
TACACS+ server IP learned through a VXLAN route 
At least one other interface in the same VRF has an IP address numerically lower than the configured source-interface IP

An upgrade or reload is not required to trigger the condition; the defect is hit as soon as the server IP is resolved through the VXLAN route.

<B>Workaround:</B>
Configure the TACACS+ server to also accept requests from the IP that the switch is incorrectly selecting (lowest IP in the VRF), and add that IP as a permitted network device.

Reach the TACACS+ server through a route that is not VXLAN-learned in that VRF if the design allows it.

Use the management VRF and mgmt0 as the TACACS+ source-interface, if the topology permits.

Remain on / revert to NX-OS 10.3(3x) where the behavior is correct.

<B>Further Problem Description:</B>
